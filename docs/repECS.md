# OBPLOT1.0 Report/Dashboard 機能拡張 要件定義・設計書

## 1. システム概要とビルド・注入アーキテクチャ
レポート出力機能は、本体アプリケーション（Sidebar）から完全に独立して稼働する単一のHTML（SPA）として実装する。
* **クラス群の静的結合（セキュア化）:** 実行時の `.toString()` による動的評価は行わず、GAS版では `include` 構文、Excel版では GitHub Actionsの `infra/build.js` によるビルドプロセスで、コアロジックを `Report.html` に静的結合する。
* **データ注入方式:** 本体側の出力処理時に、生データ（`pxrfDT`, `wdxrfDT`, `corrDT`）のみを厳密にエスケープしたJSON文字列に変換し、`Report.html` 内のプレースホルダーを置換して初期状態として展開する。
* **数式評価の安全確保:** DOM Based XSSを防ぐため、`new Function` の使用を廃止し、セキュアな数式評価ライブラリである `math.js` をCDNから読み込んで指数計算の評価エンジンとする（文字列指定の拡張性は維持）。

## 2. State管理とスキーマ駆動バインディング
ダッシュボード専用のステートマシンとして `ReportApp.state` を定義し、状態管理とUIの同期を `UIAutomator` エンジンによって全自動化（スキーマ駆動）する。

* **状態の階層分離と設定の集約:**
  状態は大きく「注入された生データ（`data`）」と「UI・グラフの設定値（`refs`）」に分かれる。`refs` は、全パネルに波及するグローバル設定（適用補正値、除外フィルター、LOD置換、シンボル定義、グラフィックスタイル）と、各パネルが個別に持つ設定に厳格に分離される。また、各プロパティの最小/最大値、入力制限、単位といった制約事項は設定オブジェクト（`RPT_CFG`）に一元化し、DOMへの動的な単位付与や入力値のリアルタイムバリデーションを全自動化する。
* **スキーマ駆動型UIとCSS（データ属性）駆動の関心分離:**
  `UI_SCHEMA` という単一の設定配列を用いてUIを構築・管理し、対象DOMのIDとバインドするStateのパスを定義するだけで双方向データバインディングが成立する。さらに、グラフタイプ変更などに伴うUI要素の表示/非表示は、JavaScriptによる直接的なスタイル操作（`style.display`）を全廃し、親コンテナへのカスタムデータ属性（`data-graphtype` 等）の付与とCSSによる状態制御へと委譲し、ロジックとスタイルの関心を完全に分離する。
* **アクションメソッドのクラス集約:**
  ユーザーのアクションはサイドバーの親コンテナで一括してイベントデリゲーションにより監視され、状態管理を担う `ReportApp` クラスの静的メソッドへ直接ルーティングされる。これにより、スキーマは純粋な「DOM定義の辞書」として軽量化され、ビジネスロジックは単一のクラス内に強固に集約される。

## 3. UI/UXと精密レイアウト制御
* **高密度プロパティ・インスペクタ:**
  設定領域は、インライン・セグメントトグルと2カラムレイアウトを活用し、限られたサイドバー領域内でスクロール量を最小限に抑えつつ、膨大な設定項目を直感的に操作できるモダンSaaS水準のUIを提供する。
* **A4コンテナの絶対寸法と印刷品質の保証:**
  画面表示時はCSSの `transform: scale()` を用いてズームアウトさせ、擬似的に画面にフィットさせる。PDF出力時（`@media print`）は、A4コンテナを絶対寸法（210mm × 297mm）で強制固定し、EChartsが生成するSVGに対して `width: 100% !important;` を適用する。これにより、ディスプレイ解像度やレンダリングタイミングに起因する縮小問題を根本から解決し、劣化のないベクター描画を完璧なA4サイズで出力する。
* **出力時（PDF/静的HTML）のUIリセットと再構築 (Export Rendering):**
  現状の出力用SVG再描画処理（DOM完全破壊からの動的再生成）が、UIの安定性と処理の確実性の観点において最も優れた最適解である。出力時（PDF印刷用iframeや静的HTMLの起動時）、元の画面からクローンされたCanvas描画の残骸をもつDOMを再利用せず、必ず初期化時に `innerHTML = ''` で完全破壊する。その後 `document.createElement` によってまっさらな状態から再生成し、初期属性として `data-renderer="svg"` を付与することで描画状態の干渉を断ち切る。また、統合出力設定（`__EXPORT_CFG__`）を用いて非印刷用UI（アクティブ枠や点線）の非表示や、ホバーの無効化（PDF時のみ）を一元管理する。
* **絶対位置マッピングによるグリッド制御:**
  行数・列数は1〜3の直接入力方式とし、内部的には `p_0` から `p_8` までの最大9つの固定IDを持つ絶対位置のパネル配列として管理する。入力値の変動に合わせて表示配列をリアルタイムに再構成することで、ユーザーの視覚的な配置感覚と内部データ構造の整合性を完全に一致させる。
* **バックグラウンドiframeによるPDF印刷と自律安全機構:**
  「PDF出力」ボタン押下時、親タブ側で描画用データを即座に事前計算し、別タブを開くことなく画面外の隠し `<iframe>` 内へHTMLを展開する。このバックグラウンドプロセス内でSVG描画と `window.print()` を完結させることで、ポップアップブロックを回避し、画面遷移を伴わないセキュアでシームレスなUXを提供する。印刷後（またはキャンセル後）は `postMessage` による同期を経てiframeを確実に取り除き、メモリリークを防止する。
* **状態複製によるHTML出力と解析ボード保存（ローカルポータビリティ）:**
  PDFと全く同じレイアウト（SVGベクター図）を維持しつつ、ツールチップ等のインタラクティブ操作が可能な「静的HTMLレポート」と、現在の作業状態・データを完全にクローンし、後日ローカル環境単体で作業再開が可能な「解析ボード」のダウンロード機能を提供する。`outerHTML` と状態オブジェクトの注入を組み合わせることで、GASバックエンドに依存しない高いポータビリティを実現する。
* **レンダリング方式の切り替え:**
  メイン画面ではリアルタイム変動するグラフのUXを最優先しCanvas、PDF出力画面では論文データへの応用可能性を考慮してベクターデータを出力するSVGとする。この使い分けは絶対ルールとして保持する。

## 4. グラフ描画と分析機能 (検量線 / 判別図)
ダッシュボードのベースとなる `pxrfDT` には、サイドバーの「補正適用トグル」と「補正適用元素」の設定状態に応じて、動的に検量線補正ロジックが適用される。
データ生成や回帰計算といった重いビジネスロジックは、Report内に記述せずロジックファイルに切り出し、DRY原則を徹底する。

* **安全マージン（見切れ防止）の自律制御:**
  グラフコンポーネント側で、X軸・Y軸のラベルが描画枠外にはみ出すのを防ぐための安全マージンを自律的に確保する。ユーザーが指定した余白が文字サイズ未満の場合にのみ、自動的に文字サイズ分の余白を上部および右部に補填する。
* **検量線 (Calibration):**
  X軸をWDXRF、Y軸をPXRFとして同一指標を描画し、回帰直線と統計値（R², 式）を引く。
* **判別図 (Discrimination):**
  X軸・Y軸それぞれに任意の指標（math.js式）を設定し、WDXRFとPXRFのデータ点を同一グラフ上に散布図として描画する。
* **視覚的区別と除外制御:**
  シンボル設定（形状・色）は一元管理され、PXRFの点は設定通りに、WDXRFの点は形状のみを引き継ぎグレー固定で描画される。さらに任意の属性と値に基づく除外データフィルターや、LOD（検出限界値）の自動置換機能を提供し、柔軟なデータ探索とノイズ排除を可能とする。

## 5. ダッシュボード状態の永続化 (お気に入りシステム)
過去に存在した `CoreMakeBU` や `localStorage` による「暗黙的な自動保存機能」は、状態の不整合や意図しない上書きを引き起こすリスクを排除するため完全に廃止した。現在は、ユーザーが意図したタイミングでのみ状態を永続化する「お気に入り（Favorite）システム」を採用している。

* **ハイブリッド・クリップボード方式によるセキュアな状態転送:**
  ReportApp内で設定された状態（`RPTST.refs` のみ。肥大化を防ぐため生データは除外）は、JSON文字列として一度クリップボードにコピーされ、それを本体ダッシュボード側のUIで受け取ってGASのプロパティ（`OBP_FAV`）に保存するハイブリッド方式をとる。これにより、iframeのクロスオリジン制約や、環境ごとのクリップボードAPIの挙動差異（APIブロック時はフォールバック用ダイアログを表示）を堅牢に吸収する。
* **ステートマシン駆動の安全な上書きUXフロー:**
  お気に入り登録時、既存の登録名と重複した場合は即座に上書きせず、対象行を警告色（赤）にハイライトしてボタンを「上書き」モードへ遷移させる。ユーザーの再確認を経てはじめて保存（成功時は緑ハイライト）されるステートマシンを実装し、過剰なトースト通知に依存しない、安全で直感的なUXを提供する。
