# 03_State_and_DataFlow.md

## 1. State管理の基本 (`CoreState.html`)
システム全体の状態は `AppSt` クラスによる単一のプロキシツリーで一元管理されています（`window.State`）。
* **取得と更新:** `State.get("path")` で値を取得し、`State.set("path", value)` で更新します。
* **リアクティビティ:** Stateが更新されると、購読しているリスナーが発火し、UIが自動的に更新されます。循環更新を防ぐガード機能も実装されています。

## 2. アプリ別ステートツリー（名前空間）の分離
アプリのフェーズや責務ごとに、明確に名前空間（ステートツリー）が分割管理されています。
* **`ENTST` (Tracer層: データ抽出フェーズ)**: `PREF`, `RAW`, `EXTR` のサブツリーを持ち、フェーズ (`phase`) の進行に応じてUIの活性/非活性を制御します。
* **`ADPST` (Tracer層: 分析・補正フェーズ)**: `ASGN`, `SYMB`, `CALB`, `PREV`, `STDZ` のサブツリーを持ちます。
* **`RPTST` (Report層: 描画・出力フェーズ)**: `dataset`（データ・フィルタ）、`config`（レイアウト・テーマ）、`panels`（最大9枚の個別パネル設定配列）を持ちます。

## 3. データ流入（ハイドレーション）アーキテクチャの違い
アプリの特性に応じて、バックエンド（GAS）からのデータ受け取りフローが異なります。
* **Tracer層 (動的フェッチ)**: `API.pullDT` 等を用いてバックエンドと非同期通信を行い、取得したデータを State にセットする動的なフェッチ駆動をとります。
* **Report層 (静的注入)**: `window.__INJECTED_DATA__` および `window.__INJECTED_FAVORITE__` というプレースホルダーを経由し、起動時に静的な文字列として注入されたデータを `RepoSt.initSt` が読み取って State をハイドレーション（初期構築）するサーバー非依存のアーキテクチャをとります。

## 4. スキーマ駆動バインディングとUI自動化 (`CoreUIPatcher` / `CoreUI.html`)
JavaScriptで直接DOMを操作するのではなく、HTMLのカスタム属性を用いてStateとUIをバインドします。
* **UIスキーマ:** `UI_SCHEMA` 等の設定配列を用いて、対象DOMのIDとバインドするStateのパスを定義するだけで双方向データバインディングが成立します。
* **アクションのクラス集約:** ユーザーのアクションは親コンテナで一括して監視され、クラスの静的メソッドへ直接ルーティングされます。
* **コンテキスト解決 (`.$active`) による動的バインディング**: 
  Report層等で配列データ（パネル）を扱う際、DOM側にインデックスを固定せず `ctx: RPTST.panels.$active` のように指定します。これが `CoreUIPatcher.ctxResolver` によって、選択中のパネル（`activePanelId`）の物理パス（例：`panels.0`）へ動的に読み替えられ、UIとシームレスに双方向バインドされます。
* **カスタム属性の規則:** CoderがUIを変更する際は、以下の属性規則に厳密に従ってください。
  * `data-action`: クリックや入力イベントのルーティング先。
  * `data-out`: Stateの値とDOM要素（テキスト、クラス等）の動的バインド (`bind: PATH; opts: PATH`)。
  * `data-ui="form"`: フォーム内のinput要素と指定Contextパスの双方向バインド。

## 5. `subscribe` による純粋関数のトリガーとデバウンス制御
Stateの変更は「見た目の変更」に留まらず、重いデータ計算や再描画をトリガーします。
* **デバウンス（遅延）制御**: スライダーの連続操作等によるブラウザのフリーズを防ぐため、`RepoReact.debounce` メソッドが `250ms` の遅延をかけて最後の1回の変更のみを評価・描画（`RepoRend.genCharts` 等）するスロットリング機構を備えています。

## 6. Stateの部分抽出と境界越え（クロスオリジン転送）
Stateはアプリ内で完結するだけでなく、外部への状態保存時にも利用されます。
* **ハイブリッド・クリップボード方式**: Report層からDash層（お気に入り永続化）へデータを戻す際、iframeのクロスオリジン制約を突破するため、Stateから `RPTST.refs`（レイアウトと設定のみ。生データは除外）を切り出して純粋なJSON文字列化し、`navigator.clipboard.writeText` を経由して転送するフローが存在します。

## 7. CSS（データ属性）駆動の関心分離
表示/非表示やUI状態の切り替えは、原則としてJavaScriptによる直接的なスタイル操作（`style.display` 等）を避け、親コンテナへのカスタムデータ属性（`data-graphtype` や `aria-selected` 等）の付与と、それに基づくCSS制御へ委譲します。
* **例外ルール:** UIのフォールバック動作や、ライフサイクル上の強制制御（印刷時のローダー非表示など）においては、直接操作（`style.display = 'none'`）を許容します。現状稼働しているコードの動作を不用意に崩さないよう、改修時は慎重に対応してください。
