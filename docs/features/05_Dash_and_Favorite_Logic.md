# 05_Dash_and_Favorite_Logic.md

## 1. Dash層の役割とデータのフェッチ
Dash層 (`Dash.html`, `Dash_App.html`) は、本体アプリケーション（サイドバー）として稼働し、Report層へのデータ供給と状態管理を担います。
* **データ注入方式:** 描画に必要な生データ（`PXRF`, `WDXRF`, `Correction`）をシートから一括でフェッチし、`Report.html` 内のプレースホルダー (`__INJECTED_DATA__`, `__INJECTED_FAVORITE__`) を置換して独立したWebアプリとして初期展開します。

## 2. ダッシュボード状態の永続化 (お気に入りシステム)
過去に存在した暗黙的な自動保存機能は、状態の不整合リスクを排除するため完全に廃止され、ユーザーが意図したタイミングでのみ状態を永続化する「お気に入り（Favorite）システム」を採用しています。

* **ハイブリッド・クリップボード方式によるセキュアな状態転送:**
  ReportApp内で設定された状態（`RPTST.refs` のみ。生データは除外）はJSON文字列としてクリップボードにコピーされ、それをDash層のUIで受け取ってGASのプロパティ（`OBP_FAV`）に保存するハイブリッド方式をとります。これにより、iframeのクロスオリジン制約を堅牢に吸収します（APIブロック時はフォールバック用ダイアログを表示）。
* **ステートマシン駆動の安全な上書きUXフロー:**
  お気に入り登録時、既存の登録名と重複した場合は即座に上書きせず、対象行を警告色（赤）にハイライトしてボタンを「上書き」モードへ遷移させます。ユーザーの再確認を経てはじめて保存されるステートマシンを実装し、安全で直感的なUXを提供します。
