# アプリケーション・アーキテクチャおよび特定仕様要件（更新版）

本ドキュメントは、`docs/` 配下の仕様（`excelECS.md`, `repECS.md`, `SAVEPOINT.md`）と現状のコードベースを統合し、本アプリケーションにおける「遵守すべきアーキテクチャ」と「特定仕様」をリストアップしたものです。

---

## 1. コア・アーキテクチャ (Architecture)

### 1.1 マルチ環境実行 (Multi-Environment Execution)
*   **GAS / Excel の完全統合**: GAS (V8/HtmlService) と Excel (Office Web Add-in) の2環境を同一のフロントエンドコードで稼働させる。
*   **PlatformAdapterによる吸収**: 実行環境の差異（API通信、ローカルストレージ・プロパティ保存）は `PlatformAdapter.html` および環境検知による依存性の注入（DI）で動的に吸収する。
*   **静的ビルド (ビルド・注入アーキテクチャ)**: Excel環境のCSP制限を回避するため、GitHub Actions (`infra/build.js`) を用いて環境依存コードを適切に統合した独立の静的HTMLを生成する。

### 1.2 状態駆動＆スキーマ駆動UI (State-Driven & Schema-Driven)
*   **単方向データフローの厳守**: `Action (ビジネスロジック) -> State (状態更新) -> CoreUIAutomator (DOM自動反映)` の一方通行フローを徹底する。
*   **命令的DOM操作の禁止**: Action層やロジックから `style.display`, `textContent`, `classList` などを直接操作することを厳格に禁止する。
*   **スキーマによる宣言的UI**: 各画面のDOMとStateのバインディングは `SCHEMA` オブジェクトの関数（`visiblePhase`, `className`, `text`, `dataset`等）に宣言し、`CoreUIAutomator` エンジンを介してリアルタイムにPatch同期させる。

### 1.3 関心の分離とロジックの純粋化 (Separation of Concerns)
*   **ドメインロジック分離**: ドメイン固有処理（検量線計算など）は `T1T2_Method` / `T3_Method` へ、汎用計算は `CoreMethod` へ完全分離する。入力から出力を返す純粋関数として実装し、外部状態・DOMに依存させない。
*   **アクション・パイプライン**: 確認ダイアログや非同期処理を伴うアクションは、必ず `CoreAction.withAsync` を経由させて統制する。

## 2. 特定仕様 (Specific Specifications)

### 2.1 PDF出力HTMLのUIリセットと再構築 (PDF Export Rendering)
現状のPDF用svg再描画処理（DOM完全破壊からの動的再生成）が、UIの安定性と処理の確実性の観点において最も優れた最適解（一番UXと処理の確実性がある構成）である。
*   **クローンDOMの完全破壊**: PDF出力用の別タブ（`__IS_PRINT_TAB__`）起動時、元の画面からクローンされたCanvas描画の残骸や状態をもつDOMを再利用せず、必ず初期化時に `grid.innerHTML = ''` で完全破壊する。
*   **クリーンビルドとSVG描画**: 破壊後、`document.createElement` によってパネルをまっさらな状態から再生成し、初期属性として `data-renderer="svg"` を付与する。ディスプレイ表示用のCanvas描画と、印刷・論文用（A4絶対寸法 210mm×297mm）の高品質なSVG描画を明確に切り分ける。
*   **事前計算による高速化**: 重い回帰計算や数式評価は親タブ側で即座に事前計算し、JSON（`window.__PRECALC_DATA__`）として別タブに注入することで、別タブでの描画処理を高速化・安全化（`math.js`利用によるXSS防止）する。

### 2.2 ダッシュボード状態の永続化 (State Persistence)
*   **作業状態の保持**: `OBP_DASH_BU` をキーとして、レイアウト構成・指標設定・グラフィックスタイル等の作業状態を `StorageAPI` を用いて環境問わず自動保存・復元する。
