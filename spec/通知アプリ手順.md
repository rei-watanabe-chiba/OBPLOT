# AppSheet Step 2 承認ワークフロー ＆ 画面UI構築 実装手順書 (v5)

## 1. 本手順書の目的と前提事項

### 1.1 概要
本書は「緊急連絡・休業通知システム」の構築ロードマップにおける **Step 2（AppSheet 承認ワークフロー ＆ UI構築）** の具体的な実装手順を解説するマニュアルである。2026年現在の AppSheet UIにおける全 15 項目のデータ設定（Column Properties）、アクション定義、Bot設定、および日本語UI表記規則を完全に網羅・定義する。

### 1.2 テスト環境 ＆ アカウント運用に関する前提方針
* **日本語UIと内部名の分離**:
  システムの挙動安定・文字化け防止のため、データベースの列名（`Name`）および送信ペイロード値（`Stored Value`）は半角英数字で保持し、画面表示名（`Display Name`）および選択肢表示名（`Option Values / Display`）において100%日本語表記化を行う。
* **項目削除（`is_protected` の廃止）**:
  保護機能は「配信対象（`target_group`）」の設定によって代替・明確化できるため、`is_protected` カラムは不要とし、スキーマ・フォーム・Botパラメータから完全に削除・除外する。
* **GWS管理者設定氏名の活用 (`USERNAME()`)**:
  Google Workspace (GWS) 管理者がアカウントに設定した表示名を AppSheet の **`USERNAME()`** 関数で動的取得する。起案・承認ボタン押下時の「その瞬間の氏名」がテキストとしてスナップショット保存されるため、年度替わりの担当者交代があっても過去の起案者・承認者名が自動的に保護される。
* **カラム名の標準化**: 起案者カラムは短く分かりやすい名称として **`drafter`（起案者メール）** および **`drafter_name`（起案者氏名）** を使用する。
* **受信テスト**: モバイルアプリ未完成の段階であるため、**FCMトークンを用いた直接配信**と**HTML受信用テストページ（Firebase Web SDK）**、および**実機**の併用で受信確認を行う。
* **デバッグ・監査ログ**: GASスクリプト（`gas-fcm-v5.gs`）および AppSheet Bot を拡張し、FCM配信結果だけでなく**承認・決裁イベント（起案、承認、修正指示等）についてもスプレッドシートの「実行ログ」シートへリアルタイム追記**する。

## 4. AppSheet 承認ワークフロー ＆ アクションの実装手順

AppSheet の `Data > Actions` にて作成するボタン・アクションの設定値です。

### 4.1 アクション定義一覧

#### ① 【起案者】「申請」アクション
* **Action Name**: `Submit_Notice`
* **Target Table**: `Notices`
* **Do this**: `Set the values of some columns in this row`
* **Set Columns**:
  * `status` ➔ `"pending"`
* **Only if this condition is true**:
  ```excel
  AND(
    [drafter] = USEREMAIL(),
    OR([status] = "draft", [status] = "revision_requested"),
    ISNOTEMPTY([selected_approvers])
  )
  ```

#### ② 【承認者】「修正指示（コメント付き）」アクション
* **Action Name**: `Request_Revision`
* **Target Table**: `Notices`
* **Do this**: `Grouped: execute a sequence of actions`
  1. `ApprovalLogs` 行追加アクション（`action_type` = `"comment_instruction"`）
  2. `Notices` の `status` を `"revision_requested"` に更新するアクション
* **Only if this condition is true**:
  ```excel
  AND(
    IN(USEREMAIL(), [selected_approvers]),
    OR([status] = "pending", [status] = "deletion_pending")
  )
  ```

#### ③ 【承認者】「承認」アクション
* **Action Name**: `Approve_Notice`
* **Target Table**: `Notices`
* **Do this**: `Set the values of some columns in this row`
* **Set Columns**:
  * `status` ➔
    ```excel
    IF(
      COUNT(SELECT(ApprovalLogs[approver_email], AND([notice_id] = [_THISROW].[notice_id], [action_type] = "approve"))) + 1 >= COUNT([selected_approvers]),
      "approved_pending_send",
      "pending"
    )
    ```
  * ※同時に `ApprovalLogs` に `action_type` = `"approve"` の行を追加。
* **Only if this condition is true**:
  ```excel
  AND(
    IN(USEREMAIL(), [selected_approvers]),
    OR([status] = "pending", [status] = "deletion_pending"),
    NOT(IN(USEREMAIL(), SELECT(ApprovalLogs[approver_email], [notice_id] = [_THISROW].[notice_id])))
  )
  ```

#### ④ 【起案者】「一斉送信を実行（通常送信 : 10分後 / 緊急即時送信）」アクション
* **Action Name**: `Execute_Send`
* **Target Table**: `Notices`
* **Do this**: `Set the values of some columns in this row`
* **Set Columns**:
  * `status` ➔ `IF([send_option] = "immediate", "sent", "scheduled_sending")`
  * `scheduled_send_time` ➔ `IF([send_option] = "immediate", NOW(), NOW() + "000:10:00")`
* **Only if this condition is true**: `[status] = "approved_pending_send"`

## 5. AppSheet Automation Bot ＆ GAS 連携設定

### 5.1 Bot (`Send_FCM_Bot`) の設定手順

1. `Automation > Bots` で **「Create a new bot」** をクリック。
2. **Event 設定**:
   * **Event Name**: `Notice_Status_Changed`
   * **Table**: `Notices`
   * **Data Change Type**: `Updates_Only`
   * **Condition**:
     ```excel
     OR(
       [status] = "sent",
       [status] = "invalidated",
       [status] = "deleted",
       [status] = "pending",
       [status] = "revision_requested",
       [status] = "approved_pending_send"
     )
     ```
3. **Task 設定 (`Call a script`)**:
   * **Task Name**: `Trigger_GAS_FCM_and_Log`
   * **Task Type**: `Call a script`
   * **Apps Script Project**: GASの**スクリプト ID**を貼り付けて検索・選択。
   * **Function Name**: **`sendFcmNotification`**
   * **Function Parameters (引数マッピング)**:
     * `noticeId` ➔ `[notice_id]`
     * `title` ➔ `[title]`
     * `body` ➔ `[body]`
     * `targetGroup` ➔ `[target_group]`
     * `sendOption` ➔ `[send_option]`
     * `actionType` ➔
       ```excel
       IFS(
         [status] = "sent", "send",
         [status] = "invalidated", "invalidate",
         [status] = "deleted", "silent_delete",
         TRUE, "approval_log"
       )
       ```
     * `deletionType` ➔ `[deletion_type]`
     * `approverEmail` ➔ `USEREMAIL()`
     * `approverName` ➔ `USERNAME()`
     * `comment` ➔ `INDEX(SELECT(ApprovalLogs[comment], AND([notice_id] = [_THISROW].[notice_id], [approver_email] = USEREMAIL())), 1)`

## 6. UI画面（Views） ＆ アクセス制御（Security Filter）の構築

### 6.1 プライマリビュー（3大画面）の設定

1. **「起案一覧」View (Table View)**:
   * **Slice (フィルタ)**: `status` ∈ {`draft`, `pending`, `revision_requested`, `approved_pending_send`, `scheduled_sending`}
2. **「決裁」View (Table View)**:
   * **Slice (フィルタ)**: `IN(USEREMAIL(), [selected_approvers])` かつ `status` ∈ {`pending`, `revision_requested`, `deletion_pending`}
3. **「施行済み一覧」View (Grouped Table View)**:
   * **Slice (フィルタ)**: `status` ∈ {`sent`, `invalidated`}
   * **Group by**: `fiscal_year` (降順)

### 6.2 画面表示・編集制御数式

* **起案フォームの編集許可 (`Editable_If`)**:
  ```excel

    [drafter] = USEREMAIL(),
    OR([status] = "draft", [status] = "revision_requested")
  )
  ```
* **`Notices` テーブルの Security Filter**:
  ```excel
  OR(
    [drafter] = USEREMAIL(),
    IN(USEREMAIL(), [selected_approvers]),
    [status] = "sent",
    [status] = "invalidated"
  )
  ```

## 7. HTML受信用テストページ ＆ スプレッドシートデバッグ検証手順

### 7.1 動作テストのフロー
1. **AppSheet アプリ上で「起案」作成**:
   * 件名「【台風に伴うテスト休校】」、本文を入力し、承認者を指定して「申請」をタップ。
2. **スプレッドシート「実行ログ」シートのデバッグログ確認**:
   * アクション `approval_log` として、操作者（`USEREMAIL()` / `USERNAME()`）・`pending` ステータス移行が記録されていることを確認。
3. **承認者アカウントで「決裁」画面から「承認」を実行**:
   * ステータスが `approved_pending_send` に更新され、ログシートに承認者コメントと承認イベントが記録される。
4. **「一斉送信」を実行（`status = "sent"`）**:
   * GASの FCM 送信ロジックが起動。
   * **検証点 A**: スプレッドシート「実行ログ」シートに `[5/5 送信成功] FCM API応答 (200 OK)` が記録される。
   * **検証点 B**: HTML受信用テストページ（またはテスト端末）にて、プッシュ通知／データメッセージがリアルタイム表示されることを確認。
