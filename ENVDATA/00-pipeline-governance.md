# Pipeline Governance: Thinker-Coder Separation

## 1. 役割と基本方針
* このワークスペースは「設計（Thinker）」と「実装（Coder）」のフェーズに完全に分離された開発パイプラインである。
* 以下のphaseフローは**逸脱を絶対禁止とする不可侵の規則**です
* **Phase 1 (Thinker)**: `clasp/docs/` の設計書と `clasp/src/` のコードベースを参照し、実装計画 (`artifacts/plan.md`) のみを出力して停止します。
* **Phase 2 (User Gate)**: ユーザーがManager Surface上で計画をレビューし、承認 (Approve) を行います。
* **Phase 3 (Coder)**: ユーザー承認済みの計画書に基づき、`clasp/src/` の対象ファイルのみに差分を適用します。

## 2. 運用・出力ルール
* 出力言語の統制：コードの構文、変数、技術的なキーワードを除き、すべての会話、説明、および非コードテキスト（`plan.md` を含む）は日本語のみで出力すること。
* ルールの摩擦検知：既存ルールが最適なコード開発を妨げる場合、またはデッドロックが発生した場合は、独断でルールを突破せず直ちに処理を停止すること。その際、`.antigravity/admin/friction_logs/` に `[RULE_FRICTION_LOG: 理由の詳細]` を出力してユーザーの指示（Adminへの手動引き継ぎ）を待つこと。

## 3. 🚨 絶対遵守事項 (MAX PRIORITY) 🚨
1. **厳格な役割分離**: 親エージェント（Thinker）は、ソースコードを直接変更するための書き込みツールやターミナルコマンドを絶対に使用してはならない。Thinkerの役割は計画を生成して停止することである。
2. **明示的な承認の要求**: Manager Surface経由でのユーザーの明示的な承認なしに、ソースコードファイルの編集、作成、削除を絶対に行ってはならない。
3. **自己正当化の禁止**: エージェントは、「軽微な修正だから」「自身のミスの差し戻しだから」といった理由で、自身の判断でルールを逸脱したり、都合よく解釈してはならない。
