# OBPLOT1.0 Report/Dashboard 機能拡張 要件定義・設計書

## 1. システム概要とビルド・注入アーキテクチャ
レポート出力機能は、本体アプリケーション（Sidebar）から完全に独立して稼働する単一のHTML（SPA）として実装する。
* **クラス群の静的結合（セキュア化）:** 実行時の `.toString()` による動的評価は行わず、GAS版では `include` 構文、Excel版では GitHub Actionsの `infra/build.js` によるビルドプロセスで、`Method.html` や `Model.html` などのコアロジックを `Report.html` に静的結合する。
* **データ注入方式:** 本体側（`T2Ctrl.openRepo`）の出力処理時に、生データ（`pxrfDT`, `wdxrfDT`, `corrDT`）のみを厳密にエスケープしたJSON文字列に変換し、`Report.html` 内のプレースホルダーを置換して初期状態として展開する。
* **数式評価の安全確保:** DOM Based XSSを防ぐため、`new Function` の使用を廃止し、セキュアな数式評価ライブラリである `math.js` をCDNから読み込んで指数計算の評価エンジンとする（文字列指定の拡張性は維持）。

## 2. State管理とスキーマ駆動バインディング
ダッシュボード専用のステートマシンとして `ReportApp.state` を定義し、状態管理とUIの同期を `UIAutomator` エンジンによって全自動化（スキーマ駆動）する。

* **状態の階層分離と設定の集約:**
  状態は大きく「注入された生データ（`data`）」と「UI・グラフの設定値（`refs`）」に分かれる。`refs` は、全パネルに波及するグローバル設定（適用補正値、除外フィルター、LOD置換、シンボル定義、グラフィックスタイル）と、各パネルが個別に持つ設定に厳格に分離される。また、各プロパティの最小/最大値、入力制限、単位といった制約事項は設定オブジェクト（`RPT_CFG`）に一元化し、DOMへの動的な単位付与や入力値のリアルタイムバリデーションを全自動化する。
* **スキーマ駆動型UIとCSS（データ属性）駆動の関心分離:**
  `UI_SCHEMA` という単一の設定配列を用いてUIを構築・管理し、対象DOMのIDとバインドするStateのパスを定義するだけで双方向データバインディングが成立する。さらに、グラフタイプ変更などに伴うUI要素の表示/非表示は、JavaScriptによる直接的なスタイル操作（`style.display`）を全廃し、親コンテナへのカスタムデータ属性（`data-graphtype` 等）の付与とCSSによる状態制御へと委譲し、ロジックとスタイルの関心を完全に分離する。
* **アクションメソッドのクラス集約:**
  ユーザーのアクションはサイドバーの親コンテナで一括してイベントデリゲーションにより監視され、状態管理を担う `ReportApp` クラスの静的メソッドへ直接ルーティングされる。これにより、スキーマは純粋な「DOM定義の辞書」として軽量化され、ビジネスロジックは単一のクラス内に強固に集約される。

## 3. UI/UXと精密レイアウト制御
* **高密度プロパティ・インスペクタ:**
  設定領域は、インライン・セグメントトグルと2カラムレイアウトを活用し、限られたサイドバー領域内でスクロール量を最小限に抑えつつ、膨大な設定項目を直感的に操作できるモダンSaaS水準のUIを提供する。
* **A4コンテナの絶対寸法と印刷品質の保証:**
  画面表示時はCSSの `transform: scale()` を用いてズームアウトさせ、擬似的に画面にフィットさせる。PDF出力時（`@media print`）は、A4コンテナを絶対寸法（210mm × 297mm）で強制固定し、EChartsが生成するSVGに対して `width: 100% !important;` を適用する。これにより、ディスプレイ解像度やレンダリングタイミングに起因する縮小問題を根本から解決し、劣化のないベクター描画を完璧なA4サイズで出力する。
* **絶対位置マッピングによるグリッド制御:**
  行数・列数は追加ボタンを廃止して1〜3の直接入力方式とし、内部的には `p_0` から `p_8` までの最大9つの固定IDを持つ絶対位置のパネル配列として管理する。入力値の変動に合わせて表示配列をリアルタイムに再構成することで、ユーザーの視覚的な配置感覚と内部データ構造の整合性を完全に一致させる。
* **事前計算によるPDF出力の高速化と自律安全機構:**
  「PDF出力」ボタン押下時、親タブ側で全パネルの描画用データ（数式評価や回帰計算を含む）を即座に事前計算し、安全にエスケープしたJSON文字列として印刷用の別タブに注入する。これにより、別タブ側での重いデータ処理ループが完全にスキップされ、驚異的な出力速度を実現する。同時に、有効な描画データが存在しない場合は出力をブロックする早期リターン（Toast警告）機構や、印刷直前の不要DOM（アクティブ枠やローディング文字）のクリーンアップ処理を備え、出力の安全性を担保する。
* **レンダリング方式の切り替え:**
  メイン画面ではリアルタイム変動するグラフのUXを最優先しCanvas、PDF出力画面では論文データへの応用可能性を考慮してベクターデータを出力するSVGとする。この使い分けは絶対ルールとして保持する。

## 4. グラフ描画と分析機能 (検量線 / 判別図)
ダッシュボードのベースとなる `pxrfDT` には、サイドバーの「補正適用トグル」と「補正適用元素」の設定状態に応じて、動的に検量線補正ロジックが適用される。
データ生成や回帰計算といった重いビジネスロジックは、Report内に記述せず `Method.html` へ共通関数（`generateChartData`）として切り出し、DRY原則を徹底する。

* **安全マージン（見切れ防止）の自律制御:**
  グラフコンポーネント側で、X軸・Y軸のラベルが描画枠外にはみ出すのを防ぐための安全マージンを自律的に確保する。ユーザーが指定した余白が文字サイズ未満の場合にのみ、自動的に文字サイズ分の余白を上部および右部に補填する。
* **検量線 (Calibration):**
  X軸をWDXRF、Y軸をPXRFとして同一指標を描画し、回帰直線と統計値（R², 式）を引く。
* **判別図 (Discrimination):**
  X軸・Y軸それぞれに任意の指標（math.js式）を設定し、WDXRFとPXRFのデータ点を同一グラフ上に散布図として描画する。
* **視覚的区別と除外制御:**
  シンボル設定（形状・色）は一元管理され、PXRFの点は設定通りに、WDXRFの点は形状のみを引き継ぎグレー固定で描画される。さらに任意の属性と値に基づく除外データフィルターや、LOD（検出限界値）の自動置換機能を提供し、柔軟なデータ探索とノイズ排除を可能とする。

## 5. ダッシュボード状態の永続化
ダッシュボード固有のLocalStorage管理クラスは廃止し、本体側の `Model.html` で定義された統合インターフェースである `StorageAPI` を直接利用するようリファクタリングした。これにより、キー名 `OBP_DASH_BU` による状態（レイアウト構成・指標設定・グラフィックスタイル等の作業状態）の自動保存・復元処理が、ブラウザ環境（GAS版）とOfficeアドイン環境（Excel版）の違いを意識することなく、単一のコードベースで堅牢に機能する。
