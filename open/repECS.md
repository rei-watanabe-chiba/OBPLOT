# OBPLOT1.0 Report/Dashboard 機能拡張 要件定義・設計書

## 1. システム概要とビルド・注入アーキテクチャ
レポート出力機能は、本体アプリケーション（Sidebar）から完全に独立して稼働する単一のHTML（SPA）として実装する。
* **クラス群の静的結合（セキュア化）:** 実行時の `.toString()` による動的評価は行わず、GAS版では `include` 構文、Excel版では GitHub Actionsの `infra/build.js` によるビルドプロセスで、`Method.html` や `Model.html` などのコアロジックを `Report.html` に静的結合する。
* **データ注入方式:** 本体側（`T2Ctrl.openRepo`）の出力処理時に、生データ（`pxrfDT`, `wdxrfDT`, `corrDT`）のみを厳密にエスケープしたJSON文字列に変換し、`Report.html` 内のプレースホルダーを置換して初期状態として展開する。
* **数式評価の安全確保:** DOM Based XSSを防ぐため、`new Function` の使用を廃止し、セキュアな数式評価ライブラリである `math.js` をCDNから読み込んで指数計算の評価エンジンとする（文字列指定の拡張性は維持）。

## 2. State管理とスキーマ駆動バインディング
ダッシュボード専用のステートマシンとして `ReportApp.state` を定義し、状態管理とUIの同期を `UIAutomator` エンジンによって全自動化（スキーマ駆動）する。

* **状態の階層分離（グローバルと個別）:**
  状態は大きく「注入された生データ（`data`）」と「UI・グラフの設定値（`refs`）」に分かれる。
  さらに `refs` の内部は、全パネルに波及するグローバル設定（適用補正値、シンボル定義、フォント、余白、軸線の太さなどのグラフィックスタイル）と、各パネルが個別に持つ設定（グラフタイプ、X/Y軸の対象指標）に厳格に分離して保持される。
* **スキーマ駆動型UI (Config-driven UI):**
  泥臭いDOM構築や個別のイベントリスナー（`addEventListener`）を廃止し、`UI_SCHEMA` という単一の設定配列を用いてUIを構築・管理する。スキーマ内で「対象DOMのID」「バインドするStateのパス」「選択肢（opts）」を定義するだけで、双方向データバインディングが自動で成立する。
* **イベントデリゲーションによる操作集約:**
  ユーザーのアクション（行追加、印刷実行、シンボル追加など）は、個別のボタンではなくサイドバーの親コンテナで一括して監視され、`data-action` 属性に対応する純粋な処理関数へとルーティングされる。これによりコード量が極限まで削減され、保守性が担保される。

## 3. UI/UXと精密レイアウト制御
* **A4コンテナの絶対寸法とズーム制御:**
  右側のメイン描画領域は、画面サイズへの単純な相対依存（%指定）を廃止し、常に「幅210mm × 高さ297mm」の絶対寸法で構築する。画面表示時（UI操作時）はCSSの `transform: scale()` を用いてズームアウトさせ、擬似的に画面にフィットさせる。これにより、UI画面とPDF出力時のピクセル計算次元が完全に一致し、完璧なWYSIWYG（見たまま出力）を実現する。
* **パネルの精密な中央配置ロジック:**
  EChartsの仕様上、軸ラベル（目盛りの数字や軸名）のサイズに依存して描画エリアが変動する。親コンテナ側はグラフコンポーネント（`Chart.html`）が内部で行っている絶対パディング計算を完全にシミュレートし、文字サイズ等から正確なパネルサイズ（px）を逆算する。これにより、CSS Grid内でグラフエリアがミリ単位で上下左右の「中央」に配置される。
* **バックグラウンドSVG印刷の完全自動化:**
  「PDF出力」ボタン押下時、システムは設定情報を保持したまま「印刷専用の裏方タブ」を生成する。この際、EChartsのレンダラーをCanvasからベクター描画の**SVGモード**へ動的に切り替え、画質を最高まで引き上げる。
  全てのグラフパネルから飛んでくる `render-finished` イベントを監視し、完全描画を検知した瞬間に印刷ダイアログ（`window.print()`）を呼び出し、処理終了後にタブを自動閉鎖する。

## 4. グラフ描画と分析機能 (検量線 / 判別図)
ダッシュボードのベースとなる `pxrfDT` には、サイドバーの「補正適用トグル」と「補正適用元素」の設定状態に応じて、動的に検量線補正ロジックが適用される。
データ生成や回帰計算といった重いビジネスロジックは、Report内に記述せず `Method.html` へ共通関数（`generateChartData`）として切り出し、DRY原則を徹底する。

* **安全マージン（見切れ防止）の自律制御:**
  グラフコンポーネント側で、X軸・Y軸のラベルが描画枠外にはみ出すのを防ぐための安全マージンを自律的に確保する。ユーザーが指定した余白が文字サイズ未満の場合にのみ、自動的に文字サイズ分の余白を上部および右部に補填する。
* **検量線 (Calibration):**
  X軸をWDXRF、Y軸をPXRFとして同一指標を描画し、回帰直線と統計値（R², 式）を引く。
* **判別図 (Discrimination):**
  X軸・Y軸それぞれに任意の指標（math.js式）を設定し、WDXRFとPXRFのデータ点を同一グラフ上に散布図として描画する。
* **視覚的区別ルール:**
  シンボル設定（形状・色）は一元管理される。PXRFの点は設定された形状・色をそのまま反映するが、WDXRFの点は形状のみを引き継ぎ、カラーは専用の「単色（デフォルトはグレー）」で固定描画して区別する。

## 5. ダッシュボード状態の永続化
本体側の `MakeBU` クラスのロジックを踏襲し、`ReportApp.state.refs` の内容を `DashBU` クラスによってローカルストレージ（キー名: `OBP_DASH_BU`）へ自動保存する。ユーザーが誤ってタブを閉じた際や、次回起動時にも、レイアウト構成・指標設定・フォントや余白などの微細なUI設定を含む作業状態を完全に復元する。
