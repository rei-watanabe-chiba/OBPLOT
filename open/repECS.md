# OBPLOT1.0 Report/Dashboard 機能拡張 要件定義・設計書

## 1. システム概要とビルド・注入アーキテクチャ
レポート出力機能は、本体アプリケーションから完全に独立して稼働する単一のHTML（SPA）として実装する。
* **クラス群の静的結合（セキュア化）:** 実行時の `.toString()` による動的評価は行わず、GAS版では `include` 構文、Excel版では GitHub Actionsの `infra/build.js` によるビルドプロセスで、`Method.html` や `Model.html` などのコアロジックを `Report.html` に静的結合する。
* **データ注入方式:** 本体側（`T2Ctrl.openRepo`）の出力処理時に、生データ（`pxrfDT`, `wdxrfDT`, `corrDT`）のみを厳密にエスケープしたJSON文字列に変換し、`Report.html` 内のプレースホルダー（例: `/*{{INJECT_REPORT_DATA}}*/`）を置換して展開する。
* **数式評価の安全確保:** DOM Based XSSを防ぐため、`new Function` の使用を廃止し、セキュアな数式評価ライブラリである `math.js` をCDNから読み込んで指数計算の評価エンジンとする（文字列指定の拡張性は維持）。

## 2. State管理スキーマ (`ReportState`)
別タブ専用のステートマシンとして `ReportState` を定義し、`dash` セクションで一元管理する。補正設定はダッシュボード全体のベースデータに影響するため、パネル個別ではなくグローバルレベル（`dash.refs` 直下）で保持する。

```javascript
ReportState = {
  dash: {
    data: {
      pxrfDT: [], wdxrfDT: [], corrDT: [] // 本体から注入された生データ
    },
    refs: {
      // --- グローバル補正設定（全パネル共通） ---
      correction: "new",       // 適用する補正値セット名（Tab2から継承）
      useCal: false,           // 補正適用トグル
      calElms: [],             // 補正適用対象元素（マルチセレクト）

      // --- グリッド構成と印刷設定 ---
      gridRows: 1, // 行数（最大3）
      gridCols: 1, // 列数（最大3）
      margins: { top: 15, bottom: 15, left: 15, right: 15 }, // 余白（mm指定）
      
      // --- UI状態 ---
      activePanelId: "p_0", // 現在サイドバーで設定対象となっているパネルID
      
      // --- パネル個別設定 ---
      panels: [
        { 
          id: "p_0", 
          graphType: "calibration", // "calibration" (検量線) | "discrimination" (判別図)
          calibVal: "",             // 検量線用指標 (例: "Fe")
          discrXVal: "",            // 判別図用X軸指標 (例: "Mn * 100 / Fe")
          discrYVal: "",            // 判別図用Y軸指標
          gphStyle: {/* defaultGraphStyle を初期値として保持 */}
        }
      ]
    },
    status: []
  }
};

```

## 3. UI/UXとレイアウト制御
* **A4縦コンテナ:** 右側のメイン描画領域はA4縦の比率を維持する（`aspect-ratio: 210 / 297;`）。設定された `margins` はコンテナのpaddingとして適用され、そのまま印刷余白となる。
* **可変サイズグリッド（CSS Grid）:** コンテナ内に最大3×3のグリッドを配置する。追加ボタンによって `dash.refs.gridRows` / `gridCols` を更新し、グラフサイズを自動分割（等分）させる。
* **アクティブパネル連動方式:** 右側のグラフパネルをクリックすることで `activePanelId` が更新される。左サイドバーのパネル個別設定UI（グラフタイプ、指標指定、シンボルなど）は、`panels` 配列内のアクティブな要素を双方向バインディングする。
* **PDF印刷対応:** `window.print()` 実行時、`@media print` により左サイドバーを非表示（`display: none`）とし、右側のA4コンテナのみを幅100%で出力する。

## 4. グラフ描画と分析機能 (検量線 / 判別図)
ダッシュボードのベースとなる `pxrfDT` には、サイドバーの「補正適用トグル(`useCal`)」と「補正適用元素(`calElms`)」の設定状態に応じて、動的に検量線補正ロジックが適用される。
* **検量線 (Calibration):**
X軸をWDXRF、Y軸をPXRFとして同一指標（`calibVal`）を描画し、回帰直線を引く。
* **判別図 (Discrimination):**
X軸・Y軸それぞれに任意の指標（`discrXVal`, `discrYVal`）を設定可能。WDXRFとPXRFのデータ点を同一グラフ上に散布図として描画する。
* **視覚的区別ルール:** シンボル設定（形状・色）は一元管理される。PXRFの点は設定された形状・色をそのまま反映するが、WDXRFの点は形状のみを引き継ぎ、カラーは専用の「単色（特色）」で固定描画される。

## 5. ダッシュボード状態の永続化
本体側の `MakeBU` クラスのロジックを踏襲し、`dash.refs` の内容をローカルストレージ（キー名: `OBP_DASH_BU`）へ自動保存する。ブラウザリロード時に復元することで、レイアウト構成や指標設定の作業状態を永続化する。

## 6. 実装ロードマップ
堅牢性を最優先とし、今回初めて導入する機構（データ注入、math.js、可変CSS Grid、特色分離描画）ごとに動作確認（検証）のフェーズを設ける。
エンドユーザーへのテンプレート配布やGitHubでの完全公開を想定しているため、特にビルド時のファイル結合とデータ注入のセキュリティ・挙動確認を序盤で確実にクリアする。

### フェーズ1: 基盤構築とセキュアデータ注入（新規機構の検証）
まずはレポート用SPAの「ドンガラ（骨組み）」を作り、本体から安全にデータが渡るか、そして新しい数式エンジンが動くかを確認します。
1. **`Report.html` のスケルトン作成と静的結合機構の改修**
* GAS用の `<?!= include('...'); ?>` の配置。
* GitHub Actions連携用の `infra/build.js` を改修し、`Report.html` 内のインクルードも静的結合できるようにする。
2. **JSONデータ注入ロジックの実装**
* 本体側 `T2Ctrl.openRepo` にて、`pxrfDT`, `wdxrfDT`, `corrDT` をエスケープ処理付きでJSON化し、プレースホルダーを置換する処理を実装。
3. **`math.js` の導入と基本評価の置き換え**
* CDN経由で `math.js` を読み込み、`Mtd.T2.Calc.evaluate` の `new Function` を `math.evaluate` へ置換。

* **【動作確認 1】**
* 本体から「レポート作成」を実行し、別タブ展開（またはダウンロード）されたHTMLのソースコードを確認。JSONが文字化け・タグ破壊を起こさず注入されているか、コンソールエラーなく `math.evaluate` が機能するかをテストします。

### フェーズ2: レポート専用Stateと可変グリッドUI（新規機構の検証）
注入されたデータを受け取り、3×3の動的レイアウトを制御するSPAコアを組み上げます。
1. **`ReportState` と永続化ロジック（`OBP_DASH_BU`）の実装**
* `dash` セクションを中心としたステートマシンを構築。
* ローカルストレージへの自動保存・復元処理を実装。
2. **A4コンテナとCSS Gridの構築**
* CSS変数（`--col-count`, `--row-count`, `--margin-top` 等）を用いたレイアウト定義。
* `dash.refs.gridRows/Cols` の変更検知による自動リサイズ機構。
3. **アクティブパネル連動UIの実装**
* 右側パネルクリックで `activePanelId` を更新。
* 左サイドバーの設定UI（グラフタイプ、指標指定）が、選択中のパネルデータと双方向バインドされる処理。

* **【動作確認 2】**
* 「＋」ボタンでグリッドが正常に分割されるか、特定パネルをクリックしてサイドバーの入力値を変更した際、そのパネルのStateだけが更新されるか。リロードして状態が復元されるか（永続化テスト）を確認します。

### フェーズ3: 分析ロジックとグラフ描画（新規機構の検証）
ダッシュボードの要である「補正の全適用」と「判別図での特色分離」を実装します。
1. **グローバル補正ロジックの適用**
* サイドバーの「補正適用トグル」と「適用対象元素」の変更を検知し、ベースとなる `pxrfDT` 全体に補正計算を反映させる。
2. **判別図（Discrimination）描画機構の実装**
* X/Y別々の指標評価ロジック。
* EChartsの `series` にWDXRF用とPXRF用の2つのデータセットを渡し、WDXRF側は「形状を引き継ぎ、色は特色（例: グレーや黒の固定色）で塗りつぶす」処理。
3. **検量線（Calibration）描画機構の移植**
* Tab2の既存ロジックをリファクタリングして適用。

* **【動作確認 3】**
* 補正トグルを切り替えた際、全パネルのPXRFプロットが一斉に移動するか。判別図において、WDXRFとPXRFの点が意図した色・形状で分離して描画されるかを確認します。

### フェーズ4: 印刷最適化と最終調整
1. **`@media print` と余白調整機能の実装**
* 印刷ダイアログ起動時にサイドバーを隠し、A4コンテナを100%幅に拡張。
* 余白設定（`dash.refs.margins`）をCSS変数経由でコンテナのpaddingに適用。

* **【動作確認 4】**
* `Ctrl+P` で印刷プレビューを開き、意図したA4比率と余白で出力されるかを最終確認します。
